# Changes since the reviewed artifact

The reviewed artifact is commit 1346300 of this repository. The responses, probes, fragment stores, `corpus.json` and `rung_stats.jsonl` files in `data/` are unchanged, and every result reported in the paper is computed from them as before.

## Verifier (`bcesv/`)

- Every variant applies one implementation of Algorithm 1: INVALID when the resolved supplying handles fall into two or more groups; otherwise ABSTAIN when a recall component has no supplying fragment, a handle is unresolved, or no handle resolved; otherwise SAFE. The reviewed verifier accepted a recall with unsupported components as SAFE, and abstained on any unresolved handle even when two resolved handles already disagreed.
- `bcesv_run_all.py` writes its outputs next to itself and prints relative file names, so its log no longer depends on where the repository is. The summary adds the share of supported recalls accepted as SAFE (`acc_sup`), abstention on cross-boundary probes, and Wilson 95% bounds for recall, precision, `fp_sup` and `acc_sup`; the log prints the values plotted in Figure 6, the number of trap responses that `FragmentOnly` flags, and the thresholds of the cohesion rule of `BcesvReconstruct`. `BcesvExact[casefold]` is added for the 93.4% acceptance quoted in §8. `bcesv_results.csv` covers both probe types for every variant (1,152 rows).
- `test_bcesv.py` has 16 unit tests: the matching rule, the decision order, deterministic noise, the cohesion rule of `BcesvReconstruct` and its independence from boundary and event labels, and the variant names.

## Exposure check (`analysis/exposure_check.py`)

Replaces `retrieval_realism_sanity.py`, its results and `RETRIEVAL_REALISM_NOTE.md`. Each distinct corpus is indexed once; the reviewed check counted the twelve condition folders as twelve corpora. Queries use the sanitized values the index holds; the reviewed check queried with tenant-visible values. Tokens are stripped of surrounding punctuation, BM25 returns no fragment with a score of zero or less, equal scores are ordered by a hash of the handle and, as a check, by file order, and a context counts as exposed only if no single event supplies all five roles. The MiniLM option (all-MiniLM-L6-v2 at a pinned revision, on the CPU) has been run and its rows are released. The log records the library versions, the queries that return fewer than ten fragments, and the counts that differ between the two tie-breaking orders, per seed and pooled. Because MiniLM scores depend on library versions, `--compare` checks a rerun against the released rows: the BM25 rows must be identical, and the MiniLM rows must give the counts reported in §7.5. A rerun goes into a new temporary folder unless `--out` names a file.

## Analysis (`analysis/`)

- `rescore_final_ci.py` writes its CSV next to itself instead of into the current directory, and writes Table 1 to `table1.txt`. The counter of supported recalls is named for what it counts: recalls produced, not correct recalls. Its printed table is unchanged and matches the original log byte for byte. The HARDENED scorer it defines is now imported by the other analysis scripts instead of copied into each.
- `scorer_sensitivity.py` prints a single percent sign where it printed `%%`, reports the median of the 24 cells as the mean of the two middle cells (EXACT 91.5%; the reviewed script took the upper middle cell, 92.0%), and drops an unused counter. It also counts, per model and unsafe rung, the components of trap recalls that equal no fragment's value but occur in a fragment's text, which HARDENED matches and EXACT does not (on the shared-vector rung, 58.7% of Mistral's components and 37.8% of Qwen's), for R1 and §8.
- `parse_fail_sensitivity.py` printed an interpretation with a 5% threshold for the safe rungs that its own results (19%) contradict; it now prints the measured bounds and the gap to the unsafe rungs, and how many parse failures are JSON recalls with a missing or null component (all 92). The column that counted parse failures as abstentions was identical to the main column by construction and is folded into the description.
- `corpus_stats.py` reported generator design parameters that differed from the runs (0% slot bridges; the runs used 1%); the block is removed. It prints the statistics over the 300 distinct trap probes that Appendix I cites, including in how many of each trap's fragments the text names its bridge entity, and REPRODUCE.md no longer promises a `p_overlap` figure that it never printed.
- `make_figure_robustness.py` draws Figure 5 with its two panels side by side, sets its labels in dark 7-point text with the unit on the axis label, prints the plotted counts, writes no PNG, and writes the PDF into a new temporary folder unless `--out` names a file (the reviewed script wrote to a fixed path under `/tmp`).
- `manual_scorer_audit.py` and `audit_labeler.py` no longer write into the released audit sample. The sampler reproduces the released sample's rows; the labeler hides the scorer's decision unless `--show-scorer` is given, and the relabeling instructions label a copy in a temporary folder. `audit_score.py` can score a relabeled copy. The sampler, the labeler and `audit_sample_README.md` define NO_MATCH alike: no recall, no abstention and no parse error.
- `paper_numbers.py` (new) prints the numbers that the paper derives from the data, including the values of Figures 3 and 4, the cells of Table 4 and the ranges of Table 6. Its [Appendix A.1] section also counts the unmatched action components that a source fragment's text contains (2,079 of 2,269) and the recalls whose every component matches a source-fragment value or lies in a source fragment's text (2,159 of 2,390), for §7.1 and Appendix A.1.
- The output of every step is released: the logs, `qualitative_cases.md`, `table1.txt`, `paper_numbers.txt` and `mnembound/mnembound_pkg/run_paper_check.log`. `rescore_final_ci.log` and `audit_score.log` are the logs of the original analysis, which the current scripts reproduce byte for byte.

## Data (`data/`)

- `metrics.json` is removed from the twelve folders. These per-condition summaries were not the output of the runs: they were rewritten after the runs, and no released script produces them. Their field `supported_recall_accuracy` counted supported probes that produced a recall, not correct recalls, and their notes stated that every such recall is fragment-supported by design, which the data contradict (`analysis/paper_numbers.txt`, §7.1). The per-cell rates of the paper are in `analysis/rescore_final_ci.csv`.
- `corpus_stats.json` is regenerated without the design-parameter block.

## Package (`mnembound/mnembound_pkg`)

- `run_paper.py` (new) holds the corpus configuration and the generation procedure of the twelve conditions, which were previously only in development run scripts. Its `check` command verifies that the package regenerates the released corpora byte for byte and counts the records that carry a bridge, the traps whose source records carry their bridge, and the prompts whose question names a raw subject; its output is released as `run_paper_check.log`.
- `summarize_rung` adds retention values left to right, so that `rung_stats.jsonl` regenerates byte for byte on every Python version (from Python 3.12, `sum()` of floats is compensated and differs in the last digit).
- Docstrings and comments describe what the code does. Development notes, planning labels, section numbers of an earlier draft, change-log wording, lint-suppression comments, and statements that the code or the data contradict are removed, among them the reviewed bridge configuration and headline metric, a realism audit, a visible thread of bridge evidence, an effect of the per-client-blocks aggregator, and functions and callers that do not exist. The fallback of the question anchor to the raw subject value is documented, and so is `scoring.is_boundary_invalid` as the event-level predicate it is. Unused imports and unused code (a stub factory, a prompt alias, four sanitizer helpers) are removed.
- The README names the models of the paper, lists the modules that exist, explains how the package's exact predicates relate to the paper's scorer, and describes `run_smoke.py` as the 100-probe smoke run it is; `run_smoke.py` drops unused code, explains the bounds of its checks of the expected rung pattern, writes into a new temporary folder unless `--out-dir` is given, and no longer prints an expected safe-rung abstention that the data contradict.
- `tests/test_day2_smoke.py` is renamed `tests/test_generation_smoke.py`. The test docstrings and comments describe what each test checks. Development history, planning labels, comments that contradicted their assertions, unused imports and variables, and checks of the source text of `agent_io.py` and `run_smoke.py` are removed; the smoke-runner tests run `run_smoke.py` with the stub instead. The two wall-clock assertions are gone: the timing test `test_performance` becomes `test_sanitizer_lookups_per_record`, which counts the sanitizer lookups of generation, and `test_scale_500_per_tenant` keeps only its size checks. The 137 tests pass.
- `pyproject.toml` names the authors and the repository, sets the version to 1.0.0 as in `CITATION.cff`, and configures pytest to run from the repository root without writing a cache.

## Repository

- `README.md`, `REPRODUCE.md` and the component READMEs are rewritten; `CHANGELOG.md`, `CITATION.cff` and `reproduce.sh` are added.
- `LICENSE` holds the full text of the Apache License 2.0 and names the authors.
- `requirements.txt` is a pip requirements file.
- `verify.sh` checks the set of files and every file's SHA-256 against `MANIFEST.sha256`, and the size of every condition, and exits non-zero on any mismatch. `generate_manifest.sh` lists the released files for it, leaving out the files that `.gitignore` leaves out. `MANIFEST.sha256` covers every released file; the reviewed manifest listed three logs that were not in the repository and an outdated README.
- `.gitignore` no longer hides the released logs.
- `paper/` holds the final paper: source, bibliography, Figure 5 and the compiled PDF with the authors' names. The anonymous version and the unused `fig_robustness.png` are removed.
